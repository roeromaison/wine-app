# おすすめ機能（好みに近い1本）

作成: 2026年8月17日

「分析結果から好みに近いワインを提案する」機能。note記事で予告していたもの。

---

## なぜ今まで作れなかったのか、なぜ作れたのか

保留していた理由は「**提案元になるワインのデータベースが無い**」でした。
市販のワイン情報には、香味を同一基準で採点した数値が付いていません。

解決策は外から探すことではなく、**手元にありました。**
maison の記録80本は、同じ人が同じ基準で13項目を採点した実測データです。
これをカタログとして使えば、距離が意味を持ちます。

つまりこの機能は「**ワインエキスパートが実際に飲んで採点した80本から、
あなたの好みに近い順に出す**」というもので、商品説明文ベースの推薦とは別物です。
記録が増えるほど候補も精度も上がります。

---

## 計算の中身

`backend/app/services/recommend.py`。3段階しかありません。

### 1. 好みプロファイルを作る

訪問者の記録のうち、**総合評価が上位1/3（最低3本）** の香味を平均します。

- 全記録の平均だと、口に合わなかったワインまで好みに混ざる
- 最高点の1本だけだと、その1本の偶然に引きずられる
- R側の分析で「★好きクラスタ」を見ているのと同じ発想で、上位群の重心を取る

同点はまとめて含めます（上位3本目と4本目が同点なら4本とも使う）。

### 2. カタログ各本との距離を測る

香味13項目の**標準化ユークリッド距離**です。軸ごとに、カタログの標準偏差で割ります。

白のタンニンのようにほぼ0で固定の軸と、果実のように広く散る軸をそのまま
足し合わせると、散る軸だけで距離が決まってしまいます。標準偏差で割ると
「その軸の中でどれだけ珍しい値か」に揃うので、13項目が対等に効きます。

`ddof=1`（不偏）は既存の分析コードと揃えてあります。
標準偏差の下限は0.5。0に近い軸で割ると距離が発散するためです。

**ものさしは色ごとに作ります。** 白と赤では香味の分布そのものが違うためです。

### 3. 近い順に返す

表示している「◯◯%」は `exp(-距離)` です。距離は1項目あたり平均で何SDずれて
いるかなので、

- 1項目あたり1SDずれ … 37%
- 0.5SD … 61%
- 0.2SD … 82%

**この数値は「おいしさの予測確率」ではありません。** 香味の近さの指標です。
記事で紹介するときは、そう書いてください。

### 近い理由・ずれの出し方

- **近い理由** … 好みプロファイルがはっきり出ている軸（|z| ≧ 0.35）で、
  その1本の値も近い（差 ≦ 0.4SD）もの。上位2つ
- **ずれ** … 差が1SD以上ある軸。1つだけ

好みが尖っていない人だと該当軸が出ないので、その場合は
「13項目全体の形が近い」を返します。理由が空のカードは信用されないためです。

### 診断タイプ名

好みプロファイルがカタログ平均から離れている軸を2つ拾って命名します。

- 向きが揃っていれば「余韻・果実高めタイプ」
- 逆向きなら「ミネラル高め・ハーブ控えめタイプ」
- どの軸も離れていなければ「バランスタイプ」

X共有用の文面もAPIが返します（`share_text`）。

## 絞り込み

画面のチェックボックス2つ。API では `min_owner_overall` と `exclude_recorded`。

**maison が総合・また買いたい度とも7点以上を付けた1本に絞る**（既定 ON）

総合7点でも「また買いたい5点」という1本があります（おいしいが、もう一度
買うほどではない）。買う前提で見せる画面なので、**両方の点数**を見ます。
OFF にすると全件が候補になり、「好みには近いが本人の評価は低い」という
正直な結果も出ます。

**すでに記録したワインを除く**（既定 ON）

ワイン名で突き合わせます。**個人版ではカタログ＝自分の記録なので、
ONのままだと候補がゼロになります。** これは想定内の挙動で、
エラーメッセージにも外し方を書いてあります。

## 購入リンクとアフィリエイト

### 設定しないと、ただの検索リンク

環境変数が未設定でも機能は動きます。その場合は各ECサイトの検索結果を開くだけで、
成果は発生しません。IDを設定して初めてアフィリエイトになります。

| 環境変数 | 内容 |
| --- | --- |
| `WINE_APP_AMAZON_TAG` | AmazonアソシエイトのトラッキングID（`◯◯◯◯-22` の形） |
| `WINE_APP_RAKUTEN_LINK_TEMPLATE` | 楽天アフィリエイトのリンク。検索語の位置を `{q}` / `{qq}` と書く |
| `WINE_APP_SITE_NAME` | Amazon規約の表記に入れるサイト名（既定「ワインをデータで飲んでいます」） |

**Render の分析API（wine-app-hp67）の Environment に設定してください。**
画面側ではなくAPI側です。リンクはAPIが組み立てて返しています。
**貼り付ける値そのものは [DEPLOY.md](DEPLOY.md) に載せてあります。**

IDは新規取得したものではなく、note記事に貼ったアフィリエイトリンクの中に
入っていたものです（`amzn.to` の転送先の `tag=`、`a.r10.to` の転送先の
楽天アフィリエイトID）。**アソシエイト契約の相手は note ではなく Amazon／楽天**
なので、同じIDを他の場所でも使えます。

楽天をテンプレート形式にしているのは、楽天のリンク書式が管理画面で発行される
ものに依存するためです。発行されたURLの検索語部分を置き換えて丸ごと入れれば、
書式が変わっても対応できます。

置き換え記号が2つあるのは、楽天のリンクが「URLの中に別のURLを入れる」形を
しているためです。`pc=` の中身は丸ごとエンコードされているので、そこに置く
検索語は**二重エンコード**しないと日本語が壊れます。

- `{q}` … 1回エンコード
- `{qq}` … 2回エンコード（**楽天のテンプレートはこちら**）

実際にリダイレクトを追って、検索結果ページに正しく着くこと、着地URLに
`scid=af_pc_etc`（楽天の成果計測パラメータ）が付くことを確認済みです。

### Amazon側でやっておくこと

アプリのURL（`https://wine-app-web.onrender.com`）を、アソシエイト・セントラルの
「ウェブサイトとモバイルアプリの一覧」に追加してください。運営規約が、リンクを
掲載するサイトの申告を求めています。note だけ登録した状態は規約上あいまいです。

規約が求める「Amazonのアソシエイトとして、〇〇は適格販売により収入を得ています。」
の表記は、`WINE_APP_AMAZON_TAG` を設定すると自動で注意書きに追記されます。

### ヴィンテージを検索語から落としている理由

単一ヴィンテージの商品ページは1年ほどで消えます。80本分のASINや商品IDを
個別管理すると、いずれ全部リンク切れになります。

そこで `search_query` は「2024」のような4桁年を除いた文字列にしてあります
（`scripts/build_catalog.py` の `to_search_query`）。
生産者名とキュヴェ名だけ残しておけば、年が変わっても検索は当たり続けます。

### ステマ規制への対応

2023年10月から、広告であることの表示が必要です。**note記事だけでなく、
アプリの画面にも要ります。**

表示漏れが起きないよう、**開示文はAPIのレスポンス（`disclosure`）に含めて**
画面が必ず描画する形にしてあります。アフィリエイトIDが設定されているときは
アフィリエイト用の文面、未設定のときは「検索結果を開きます」に切り替わります。

## カタログの作り直し

記録を追加したら実行します。

```powershell
cd C:\Users\User\Documents\wine-app\backend
```
```powershell
.venv\Scripts\python scripts\build_catalog.py "..\..\wine-notes\data\wine_log.csv"
```

`backend/app/data/catalog.json` が上書きされます。**APIに同梱されるので、
反映するには GitHub に push して Render を再デプロイする必要があります。**

`build_sample.py`（デモ用サンプル）とは目的が違うので注意してください。

| | sample-notes.json | catalog.json |
| --- | --- | --- |
| 用途 | 訪問者が「自分の記録」として読み込むデモ | 訪問者に提案する候補 |
| 商品名 | 連番に置換 | **残す**（無いと提案にならない） |
| 価格 | 落とす | 残す（価格帯の目安） |
| 購入先・日付・メモ | 落とす | 落とす |

カタログに残しているのは**ワイン側の属性**と、maison が付けた総合評価・
また買いたい度だけです。飲んだ人の情報（いつ・どこで買ったか・メモ）は入れていません。

## 正直に書いておくこと

記事にするときに、ここを省かないでください。

- **80本は少ない。** 提案が「近い」といっても、候補が80本しか無い中での近さです
- **%は香味の近さであって、おいしさの予測ではない**
- **好みプロファイルは上位1/3の平均。** 記録が3本なら3本の平均で、当然荒い
- **maison の採点はブレる。** 1人が1回ずつ付けた点数で、再現性の検証はしていない

この機能の価値は精度ではなく、**同一基準で採点された実データと比べられること**です。
そこを誇張しない書き方が、これまでの記事と揃います。
